# ADR-0013: authenticated transport boundary (implementation in progress)

Status: draft for #14. Not an acceptance PASS or deployment authorization.

The versioned dream.v1 protobuf service generates Go DTOs, gRPC, a direct
HTTP/JSON gateway and OpenAPI v2. DTO translation stays in adapters/transport.
Document responses explicitly contain versioned canonical domain JSON; protobuf
serialization is never used for domain hashes. scripts/generate-api.py pins the
compiler archive checksum and local Go plugin versions, regenerates into a
separate directory and compares every generated byte. The compatibility baseline
pins field numbers/names/types/cardinality and RPC request/response identities.
New unregistered generation inputs still fail the earlier artifact gate.

Configured SHA-256 bearer digests map to exact server-owned caller, role,
principal, purpose and operator/namespace/world/branch/run. There is no header
selected identity or unauthenticated default. Credential hashes must represent
random secrets with at least 32 bytes of entropy; syntax checks cannot prove
entropy. Credentials are supplied by trusted host composition, not an API.
Tokens and their digests are not journaled or returned. Actor, external and
research calls use separate role checks and current ViewService permits.

Both gRPC and the generated direct gateway authenticate, scope-check and
revalidate before returning. Direct registration does not run gRPC interceptors,
so guardedBackend repeats authorization on that path. Proxy metadata cannot
supply a second bearer credential. Listeners are owned by the wrapper: explicit
development allows loopback only; other configurations require TLS 1.2 or newer
and configured certificates. Message sizes, headers and request durations are
bounded. Underlying errors are sanitized before transport output.

RuntimeReady checks the actual PostgreSQL session and all reachable roles for
superuser/bypass/role-creation/database-creation and Dream table ownership, and
requires the existing forced-RLS tables and runtime writer privileges. It does
not provision roles, run migrations or accept migration-owner connections.

The process-local burst limiter is additional protection. The required admission
callback uses Store.AdmitRequest for a permanent versioned request journal. New
store instances and minute windows do not reset total usage; timestamp rollback
cannot refund requests within a prior window. Stable credential IDs preserve the
ledger across secret rotation. New host credential IDs represent explicit new
budgets, not automatic retries. Failed requests still consume admission. Runtime
operation idempotency is separate from admission accounting.

The backend reuses manifests, fenced runtime operations, snapshot/replay services
and actor/research/external views. It serializes local command execution and
renews a bounded lease cache. Completed operation retries return their durable
receipt before acquiring a lease, including after terminal state. A fresh process
must respect outstanding lease expiry/fencing rather than stealing a lease.
Fork destinations require an existing host mapping for the same researcher and
principal and an existing child view permit. Unknown scopes cannot be minted by
supplying a child branch name.

Export submission persists only request/manifest metadata, never exported bytes.
Downloads reconstruct under current role, view operation and source authorization,
then require the original manifest hash/size. Private exports use the existing
approved quotation protocol and explicit Export rights. Research exports use
current replay source checks, including dependencies outside a requested time
filter. Pagination is bounded byte slicing with per-page and whole-body checksums;
a cursor binds the manifest, not authority. No URL/file destination is accepted.
Delivered bytes cannot be retroactively erased. Source identifiers in durable
request metadata remain subject to the existing metadata-retention limitations.

The external port exposes restricted observations and bounded requested intents
(wait/observe/ask). An intent is an observation submitted to the trusted handler;
it is not evidence that an action completed or a latent-state assignment. The
example client has no research/export methods. Transport handlers and model
execution remain trusted host composition; client payloads cannot select them.

## Current evidence

- Authentication fail-closed, forged/expired/revoked session negatives and
  concurrent burst/total ledger tests pass under the race detector.
- Real loopback gRPC/HTTP equivalence, IDOR, duplicate/proxy credential rejection,
  direct gateway denial and revoke-before-return tests pass.
- Real PostgreSQL non-owner session, indirect table-owner rejection, durable
  admission across new instances/windows/clock rollback tests pass.
- Real gRPC + PostgreSQL + synthetic handler tests pass for role separation,
  controls, idempotent retries/conflicts, snapshots, checksummed export roundtrip,
  cross-principal download denial and revocation after submission.
- Full make verify passes, including generated drift, all normal/race tests,
  disposable PostgreSQL, migrations/purge-aware restore and existing binary help.

## Remaining engineering gates (not yet PASS)

- Add transport integration coverage for private export and source revocation,

- Strengthen negative compatibility/generation probes and export cursor/filter
  tests; finish requirement mapping and independent exact-SHA review evidence.
- No READY_FOR_CLAUDE until these gates and final full verification are complete.

No paid/model runs, deployment, real credential provisioning, main changes or
scientific-validity claims are introduced. The local 24-hour supervisor remains
BLOCKED_PREFLIGHT; this implementation is not a persistent worker service.
